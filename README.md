# Supergraph

Воксельный движок с нативным физически-корректным рендером, спроектированный
под интегрированную графику класса Intel UHD 620.

Идея проекта: качество картинки, которое в Minecraft достигается только
шейдер-паками, должно быть **свойством самого движка**, а не надстройкой над
чужим пайплайном. Здесь нет ни шейдер-паков, ни текстур-паков — всё небо,
освещение, вода, облака и материалы считаются или генерируются движком.

> **Продолжаете работу над проектом?** Начните с [CONTEXT.md](CONTEXT.md) —
> там исходная постановка, обоснование всех архитектурных решений, полная
> хронология найденных багов, история оптимизации, справочник отладочного API и
> список инвариантов, которые легко сломать по незнанию.

## Быстрый старт

```bash
npm install
npm run dev          # http://127.0.0.1:5173
```

Открывать в Chrome или Edge. Управление:

| Клавиши | Действие |
|---|---|
| `WASD` | движение |
| `Space` | прыжок / всплытие |
| `Shift` | красться (в полёте — вниз) |
| `Ctrl` | бег (в полёте — ускорение) |
| `F` | режим полёта |
| `ЛКМ` / `ПКМ` | сломать / поставить блок |
| `1`–`9`, колесо | выбор блока |
| `F3` | статистика кадра |
| `F4` | настройки графики |
| `Esc` | освободить курсор |

`?seed=12345` в адресной строке фиксирует мир — это нужно для воспроизводимых
замеров производительности.

Сборка статики: `npm run build` → `dist/`.

## Что реализовано

### Мир

* **Чанки 32×32×192**, шесть секций по вертикали. Footprint 32 (а не 16, как в
  Minecraft) выбран сознательно: на интегрированной графике доминируют
  накладные расходы драйвера на draw call, поэтому меньше и крупнее — выгоднее,
  даже ценой более дорогого перестроения меша.
* **Генерация рельефа** на четырёх низкочастотных полях (континентальность,
  эрозия, хребты, «странность») плюс детализация полного разрешения. Поля
  считаются на **глобальной решётке** с шагом 4 блока — именно это гарантирует,
  что дерево, посаженное из соседнего чанка, встанет ровно на ту землю, которую
  этот чанк сгенерирует.
* **19 биомов** по непрерывным климатическим полям, с плавным смешением цветов
  на решётке (радиус 24 блока) — без резкой границы на стыке.
* **Пещеры** — пересечение двух независимых шумовых полей около нуля (даёт
  червеобразные тоннели, а не «швейцарский сыр») плюс клеточный шум для залов.
  Поле считается на решётке 4³ и интерполируется — в 64 раза дешевле повоксельного.
* **Реки**, руды, деревья шести видов, трава, цветы, кактусы, снег.
* **Greedy meshing** с per-vertex AO и мягким светом. Вершина — 12 байт.
  Индексный буфер один на весь мир (паттерн `0,1,2, 0,2,3`), потому что мешер
  всегда пишет по 4 вершины на квад.
* **Заливка света** (skylight + blocklight) считается с 4-блочной юбкой из
  соседних колонок, поэтому под навесом на границе чанков нет шва.

### Многопоточность

Данные мира лежат в `SharedArrayBuffer` — воркеры генерируют, освещают и
меширують чанки, читая соседей напрямую, без копирования. Для этого dev-сервер
отдаёт заголовки COOP/COEP. Если изоляции нет (например, открыли `dist` через
`file://`), движок прозрачно переключается на однопоточный конвейер с бюджетом
времени на кадр — тот же код, другой планировщик.

Жёсткий порядок зависимостей — то, что позволяет строить меш **сразу правильно**,
без переделки при появлении соседей:

```
generate  →  без зависимостей
light     →  окрестность 3×3 сгенерирована
mesh      →  окрестность 3×3 освещена
```

### Рендер

Форвардный, с порядком проходов:

```
1  каскады теней          глубина от солнца, 2–4 каскада
2  opaque                 PBR, тени, атмосфера
3  cutout                 листва и растения, alpha-test
4  трава                  GPU-инстансинг, ноль CPU
5  небо                   только там, где ничего не нарисовано
6  облака                 четверть разрешения, композит по depth-тесту
7  копия кадра            чтобы вода видела, что за ней
8  вода                   SSR, преломление, поглощение
9  translucent            стекло и лёд
10 погода                 дождь и снег
11 TAA                    репроекция через глубину, без буфера скоростей
12 bloom                  порог, цепочка downsample, tent upsample
13 автоэкспозиция         редукция до 1×1, адаптация на GPU
14 composite              ACES, виньетка, аберрация, зерно
15 SSAO                   для следующего кадра
```

**Атмосфера** — модель Hillaire 2020: LUT трансмиттанса (256×64) и
многократного рассеяния (32×32) считаются один раз при запуске, sky-view LUT
(192×108) — каждый кадр. Всё остальное — купол неба, цвет тумана, ambient на
каждой грани блока, отражение в воде — читает эту одну маленькую текстуру.
Закат краснеет потому, что коротковолновая часть спектра действительно
рассеялась на более длинном пути, а не потому, что кто-то задал градиент.

**Тени** — каскады, подогнанные под ограничивающие *сферы* срезов пирамиды
видимости. Сфера инвариантна к повороту камеры, поэтому проекция не «дышит» при
осмотре; вместе с привязкой центра к целым текселям это убирает ползание краёв.
Дальние каскады обновляются раз в 2 и 4 кадра.

**Материалы** — три массива текстур: альбедо, нормаль/шероховатость/AO и
высота/F0/подповерхностное/свечение. Источников два и они дополняют друг друга:

* **LabPBR-пак**, если он распакован в `public/pack/`. Работает любой из
  сотен существующих PBR-паков — формат стандартный. Он даёт настоящее поле
  высот для параллакса, измеренный F0 вместо предположения 0.04, потексельное
  свечение и подповерхностное рассеяние.
* **Процедурная генерация** для всего остального. Она покрывает воду и лаву,
  которых паки не поставляют (их рисует шейдер), и работает целиком, если пака
  нет: 46 материалов при 128 px это около 9 МБ видеопамяти и ноль байт на диске.

```bash
node scripts/extract-pack.mjs        # достаёт из .zip в корне только нужные
                                     # ~130 файлов в public/pack/
```

**Трава** — ни одной вершины на CPU. Каждый инстанс выводит свою позицию из
`gl_InstanceID` по сетке вокруг камеры и читает высоту рельефа и тип
поверхности из тороидального атласа, который поддерживает загрузчик чанков.
Ячейка не с травой схлопывается в вырожденный треугольник.

**Вода** — сумма волн Герстнера (высота и градиент из одного вычисления),
поглощение по Бугеру–Ламберту по глубине столба, экранные отражения с откатом
на реальное небо, пена по разнице глубин, рябь от дождя.

**Облака** — объёмный рейтрейс по двум запечённым 3D-текстурам (форма 64³ и
детали 32³, разделение shape/detail из Nubis). Энергосохраняющее интегрирование
отрезка позволяет 20 шагам выглядеть как 80.

## Производительность: как измерялось и что вышло

Целевое железо — то, на котором проект и разрабатывался:
**Intel Core i5-8350U + UHD 620, 12 ГБ**, Chrome/ANGLE D3D11.

### Методика

Сначала я мерил «включил/выключил фичу» и получал бессмыслицу: отключение
облаков *замедляло* кадр, половинное разрешение тоже. Причина — **тепловой
троттлинг**: за 4+ минуты непрерывной нагрузки ноутбучный UHD 620 теряет
примерно треть производительности, и абсолютные числа, снятые в начале и в
конце прогона, несравнимы.

Поэтому в репозитории три инструмента:

| Скрипт | Что делает |
|---|---|
| `scripts/gputime.mjs` | **Основной.** Реальные GPU-миллисекунды по каждому проходу через `EXT_disjoint_timer_query_webgl2`, плюс разбивка CPU по фазам цикла. |
| `scripts/breakdown.mjs` | A/B по фичам, где **каждый случай обрамлён свежим замером базы** — это снимает тепловой дрейф. |
| `scripts/perf.mjs` | Сводка по пресетам. Читать медиану, не среднее. |
| `scripts/smoke.mjs` | Проверка, что все шейдеры компилируются и кадр рисуется. |
| `scripts/gallery.mjs` | Скриншоты в разное время суток. |
| `scripts/shoot.mjs` + `materials.html` | Контактный лист всех процедурных материалов. |

Все они запускаются против живого dev-сервера и принимают `?seed=N`.

### Что нашлось и во сколько обошлось

Порядок — по величине выигрыша:

| Находка | Было | Стало |
|---|---|---|
| **У воды не отсекалась верхняя грань между двумя блоками воды** — в двадцатиблочном океане рисовалось двадцать наложенных полупрозрачных поверхностей | 107 мс | **5.5 мс** |
| **Облака считали шум Ворли аналитически** — 81 хеш на сэмпл, ×6 шагов марша к солнцу ×20 шагов ×41k пикселей ≈ 500 млн хешей на кадр | ~40 мс | **0.39 мс** (запёк в 3D-текстуры) |
| **SSR и детальные нормали воды считались на каждом пикселе океана** | — | отсечка по расстоянию |
| **Depth prepass** существовал только ради нормалей для SSAO | 7 мс GPU + половина всех draw call | **удалён** (SSAO восстанавливает нормали из глубины и работает по кадру назад) |
| **Листва отдавала все 6 граней** каждого блока кроны | 705k квадов | **173k** |
| Дальние каскады теней перерисовывались каждый кадр | — | обновление раз в 2 и 4 кадра |
| Выгрузка мешей в GPU шла пачками по мере готовности | 1% low 19 fps | **28 fps** (адаптивный бюджет на кадр) |

Суммарно: средний пресет прошёл путь **10.5 → 35 fps**, при том что качество
картинки не снижалось — наоборот, по дороге облака впервые заработали вообще.

Плюс исправленные по ходу **настоящие баги**, а не только скорость:

* Позиции вершин писались в `Uint16Array`, и крестовидное растение на краю
  секции давало отрицательную координату → заворот в 65535 → квад улетал на
  8192 блока и рисовался как «провод» через всё небо.
* У граней `+X` и `-Z` вертикальной осью текстуры была `u`, а у `-X`/`+Z` — `v`:
  травяная кромка, слои песчаника и доски были повёрнуты на 90° на половине
  граней каждого блока.
* Композит облаков читал текстуру глубины, **прикреплённую к тому же FBO**, в
  который рисовал, — undefined behaviour, из-за которого облаков не было видно
  вообще.
* Покрытие облаков задавало нижнюю границу remap, поэтому при среднем
  покрытии 0.2 требовалась базовая форма выше 0.8 — небо оставалось пустым.
* Интенсивность солнца гасилась вручную по высоте, хотя физическое затухание
  уже даёт трансмиттанс: двойной учёт делал закат и сумерки чёрными.
* Цвета биомов задавались как sRGB, а использовались как линейное альбедо —
  трава была вымыта в белый.
* Отсутствие автоэкспозиции: полдень пересвечен при экспозиции, при которой
  виден закат, и наоборот.

### Текущие числа

Замер на холодной машине, 1280×720, фиксированный сид, камера вращается на
360° (то есть в выборку попадают и открытый океан, и лес):

| Пресет | Внутреннее разрешение | Медиана | Среднее | 1% low |
|---|---|---|---|---|
| Низкий | 896×504 | **57 fps** | 52 fps | 28 fps |
| Средний | 1088×612 | **55 fps** | 36 fps | 14 fps |
| Высокий | 1280×720 | **28 fps** | 25 fps | 8 fps |
| Ультра | 1280×720 | 12 fps | 12 fps | 4 fps |

Разбивка GPU на среднем пресете (`scripts/gputime.mjs`, 28.8 мс на кадр):

```
chunks opaque    9.02 мс   37%
water            5.49 мс   23%
grass            2.09 мс    9%
shadow maps      1.84 мс    8%
scene copy       1.07 мс    4%
ssao             1.05 мс    4%
composite        1.01 мс    4%
taa              0.91 мс    4%
bloom            0.64 мс    3%
clouds           0.39 мс    2%
sky              0.30 мс    1%
sky LUT          0.23 мс    1%
chunks cutout    0.05 мс    0%
-------------------------------
сумма GPU       24.14 мс
CPU в render()  22.91 мс
```

**Честная оценка.** Средний пресет держит 55 fps по медиане и 36 по среднему —
цель достигнута по медиане, но не по «худшему кадру»: 1% low в 14 fps означает
заметные рывки при подгрузке новых чанков. Низкий пресет комфортен полностью
(57/52/28). Высокий играбелен (28 fps). Ультра на UHD 620 — режим для
скриншотов.

GPU (24 мс) и CPU (23 мс) почти в паритете. Может показаться, что упор в
накладные расходы драйвера на draw call — **это проверено и опровергнуто**:
рост числа вызовов отрисовки в полтора раза не меняет время CPU вообще, то есть
главный поток не подаёт команды, а ждёт GPU.

Настоящий предел измерен и разобран в [CONTEXT.md, раздел 7](CONTEXT.md):
**19.2 мс кадра не зависят от разрешения** — это обработка примерно 1.1 млн
вершин, и никакая смена стека её не сократит. Отсюда план ниже.

## Известные проблемы

**Тёмные полублоковые треугольники на снежных и песчаных террасах.** Самый
заметный оставшийся артефакт. Регулярные тёмные треугольники размером в
половину квада, одинаково ориентированные (по диагонали разбиения квада),
видны на плоских снежных площадках у берега.

Что уже исключено измерением (`scripts/debugview.mjs` выводит каналы шейдера
чанков по отдельности):

* **не тени** — сохраняются при честно выключенных тенях
  (`scripts/diag.mjs ... shadowsEnabled true false`);
* **не SSAO** — канал SSAO в этих местах равномерно белый;
* **не запечённый свет и не вершинный AO** — оба канала равномерно белые;
* **не альбедо** — в режиме сырого альбедо поверхность однородна, то есть
  геометрия чанка на месте и дыр в ней нет;
* **не инстансированная трава** — сохраняются при `grassEnabled: false`.

При этом в режиме нормалей на этих местах видна нормаль **боковой**, а не
верхней грани, и артефакт всегда занимает ровно половину квада по его
диагонали — то есть один из двух треугольников затеняется или перекрывается.

По ходу поиска найдены и исправлены четыре настоящие ошибки, но ни одна не
оказалась причиной именно этой пилы:

1. У воды не отсекалась верхняя грань между двумя блоками воды — в
   двадцатиблочном океане рисовалось двадцать наложенных полупрозрачных
   поверхностей (это же объясняло 107 мс на проходе воды).
2. Снежные биомы использовали снег как материал поверхности, поэтому слой
   снега из декоратора на такие колонки не клался — получалось поле ямок в
   один блок.
3. В теневом проходе отсекались передние грани — приём для замкнутых тел,
   тогда как воксельный меш это оболочка без внутренних граней.
4. При выключенных тенях шейдер всё равно читал никогда не отрисованную карту
   теней и получал произвольные тёмные пятна.

Следующий шаг, который я не успел сделать: выводить бакеты по отдельности
(opaque / cutout / translucent / water) в разные цвета и найти, какой из
проходов реально закрашивает эти пиксели. Инструмент для этого уже есть —
`uDebugView` в `chunk.frag.glsl`, нужно добавить режим «сплошной цвет по
бакету».

Кроме этого:

* Абсолютные FPS на этом ноутбуке гуляют примерно в 1.5 раза между холодным и
  прогретым состоянием. Для сравнения вариантов пользуйтесь
  `scripts/gputime.mjs` (GPU-миллисекунды по проходам) или
  `scripts/breakdown.mjs` (чередование с базой), но не абсолютными числами
  из последовательного прогона.
* Снег кладётся и на подводные колонки на мелководье.
* Смена пресета пересобирает все шейдерные программы синхронно — заметная
  пауза при перетаскивании ползунка настроек.

## Что делать дальше

Подробная дорожная карта с оценками стоимости, порядком работ и разбором
конкретных визуальных референсов — в [CONTEXT.md, раздел 12](CONTEXT.md).
Коротко:

1. **LOD дальних чанков.** Снимает ~5 мс с самого дорогого прохода и заодно
   даёт дальность прорисовки уровня Distant Horizons. Одна работа — две цели.
2. **Occlusion culling.** Для воксельного мира дёшев: трассировка луча по уже
   имеющейся карте высот рельефа, без синхронизации с GPU.
3. **Parallax occlusion mapping.** Главный скачок в детализации блоков. Карта
   высот уже считается в генераторе материалов, её надо начать сохранять.
4. **Плотность травы + LOD травы.**
5. **Воксельное глобальное освещение.** Приближение к path-traced GI, дешёвое
   именно потому, что мир воксельный.
6. **Загрузка LabPBR-паков.** Пак `Roundista 128x R32.zip` уже лежит в корне,
   покрытие проверено: 44 из 46 наших материалов.

Пункты 1–2 обязаны идти первыми: они освобождают бюджет кадра, без которого
остальное некуда добавлять. Пункты 3 и 6 делаются одной задачей — им нужна
общая третья текстура-массив.

Не сделано из задуманного помимо этого: звук, сохранение мира на диск,
инвентарь и крафт, мобы, мультиплеер.

```
  world/      блоки, шум, генератор, биомы, свет, мешер, стриминг, воркер
  render/     GL-обёртки, шейдерная система, кадровый граф, небо, тени,
              процедурные материалы, 3D-шум облаков, GPU-профайлер
  player/     физика, коллизии, камера
  ui/         HUD, оверлей статистики, панель настроек
  debug/      контактный лист материалов
scripts/      смоук-тест, галерея, бенчмарки, профайлер
```

Шейдеры — в `src/render/shaders/`, с собственным препроцессором `#include`
(`src/render/shader.ts`). При ошибке компиляции в консоль печатается лог
драйвера вместе с фрагментом собранного исходника вокруг проблемной строки.
